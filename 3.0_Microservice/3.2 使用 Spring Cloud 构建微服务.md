## 1. 微服务架构概述

### 1.1 什么是微服务？

微服务架构是一种将单一应用程序开发为一组小型服务的方法，每个服务运行在自己的进程中，并使用轻量级机制（通常是 HTTP API）进行通信。

### 1.2 单体架构 vs 微服务架构

#### 1.2.1 单体架构（Monolithic Architecture）

```text
┌─────────────────────────────────────┐
│           单体应用程序               │
│  ┌─────────┬─────────┬─────────┐    │
│  │  用户   │  订单   │  支付   │    │
│  │  管理   │  管理   │  管理   │    │
│  └─────────┴─────────┴─────────┘    │
│  ┌─────────────────────────────┐    │
│  │        共享数据库           │    │
│  └─────────────────────────────┘    │
└─────────────────────────────────────┘
```

**特点：**

- 所有功能模块打包在一个应用中
- 共享数据库和运行时环境
- 部署简单，但扩展困难

#### 1.2.2 微服务架构（Microservices Architecture）

```text
┌─────────┐    ┌─────────┐    ┌─────────┐
│  用户   │    │  订单   │    │  支付   │
│  服务   │    │  服务   │    │  服务   │
│ ┌─────┐ │    │ ┌─────┐ │    │ ┌─────┐ │
│ │ DB  │ │    │ │ DB  │ │    │ │ DB  │ │
│ └─────┘ │    │ └─────┘ │    │ └─────┘ │
└─────────┘    └─────────┘    └─────────┘
     │              │              │
     └──────────────┼──────────────┘
                    │
            ┌─────────────┐
            │  API 网关   │
            └─────────────┘
```

**特点：**

- 每个服务独立开发、部署和扩展
- 服务间通过 API 进行通信
- 数据库分离，服务自治

### 1.3 微服务的优势与挑战

#### 1.3.1 优势

1. **技术多样性**：不同服务可以使用不同的技术栈
2. **独立部署**：服务可以独立发布和更新
3. **故障隔离**：单个服务的故障不会影响整个系统
4. **团队自治**：小团队可以独立负责特定服务
5. **可扩展性**：可以针对特定服务进行水平扩展

#### 1.3.2 挑战

1. **分布式系统复杂性**：网络延迟、故障处理
2. **数据一致性**：分布式事务管理
3. **服务治理**：服务发现、配置管理
4. **运维复杂度**：监控、日志聚合
5. **测试复杂性**：集成测试和端到端测试

## 2. Spring Cloud 简介

### 2.1 什么是 Spring Cloud？

Spring Cloud 是一系列框架的有序集合，它利用 Spring Boot 的开发便利性简化了分布式系统基础设施的开发。

### 2.2 Spring Cloud 的核心理念

- **约定优于配置**：提供默认配置，减少样板代码
- **开箱即用**：集成常用的微服务组件
- **云原生**：支持云平台部署
- **生态丰富**：与 Spring 生态系统无缝集成

### 2.3 Spring Cloud 版本关系

| Spring Cloud 版本 | Spring Boot 版本 | 发布时间 |
|-------------------|------------------|----------|
| 2023.0.x (Leyton) | 3.2.x | 2023年 |
| 2022.0.x (Kilburn) | 3.0.x, 3.1.x | 2022年 |
| 2021.0.x (Jubilee) | 2.6.x, 2.7.x | 2021年 |
| 2020.0.x (Ilford) | 2.4.x, 2.5.x | 2020年 |

### 2.4 Spring Cloud 主要组件

```text
Spring Cloud 生态系统
├── 服务发现
│   ├── Eureka (Netflix)
│   ├── Consul (HashiCorp)
│   └── Zookeeper (Apache)
├── 服务调用
│   ├── OpenFeign
│   └── RestTemplate
├── 负载均衡
│   └── Spring Cloud LoadBalancer
├── 断路器
│   ├── Hystrix (已停止维护)
│   └── Resilience4j
├── 配置管理
│   └── Spring Cloud Config
├── API 网关
│   ├── Spring Cloud Gateway
│   └── Zuul (已停止维护)
└── 链路追踪
    ├── Sleuth
    └── Zipkin
```

## 3. 核心组件介绍

### 3.1 服务注册与发现

#### 3.1.1 为什么需要服务注册与发现？

在微服务架构中，服务实例的数量和位置是动态变化的：

- 服务实例可能因为故障而停止
- 服务实例可能因为扩容而增加
- 服务实例的 IP 地址可能发生变化

#### 3.1.2 服务注册与发现模式

```text
服务注册与发现流程：

1. 服务启动时注册到注册中心
   Service A ──register──> Registry

2. 服务定期发送心跳保持注册状态
   Service A ──heartbeat──> Registry

3. 客户端从注册中心获取服务列表
   Client ──discover──> Registry

4. 客户端直接调用服务
   Client ──call──> Service A
```

### 3.2 负载均衡

#### 3.2.1 客户端负载均衡 vs 服务端负载均衡

**服务端负载均衡**：

```text
Client → Load Balancer → Service Instance 1
                      → Service Instance 2
                      → Service Instance 3
```

**客户端负载均衡**：

```text
Client (with LB logic) → Service Instance 1
                      → Service Instance 2
                      → Service Instance 3
```

#### 3.2.2 负载均衡算法

1. **轮询（Round Robin）**：依次调用每个服务实例
2. **随机（Random）**：随机选择服务实例
3. **加权轮询（Weighted Round Robin）**：根据权重分配请求
4. **最少连接（Least Connections）**：选择连接数最少的实例

### 3.3 服务间通信

#### 3.3.1 同步通信 vs 异步通信

**同步通信**：

- HTTP/REST
- RPC (gRPC)
- 特点：简单直接，但可能造成级联故障

**异步通信**：

- 消息队列 (RabbitMQ, Kafka)
- 事件驱动架构
- 特点：解耦性好，但复杂度较高

## 4. 服务注册与发现

### 4.1 Eureka 架构

Eureka 是 Netflix 开源的服务发现组件，采用 AP（可用性和分区容错性）设计。

```text
Eureka 架构图：

┌─────────────────┐    ┌─────────────────┐
│   Eureka        │    │   Eureka        │
│   Server 1      │◄──►│   Server 2      │
└─────────────────┘    └─────────────────┘
         ▲                       ▲
         │                       │
    ┌────┴────┐             ┌────┴────┐
    │ Service │             │ Service │
    │    A    │             │    B    │
    └─────────┘             └─────────┘
```

### 4.2 Eureka Server 配置

#### 4.2.1 添加依赖

```xml
<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
    <dependency>
        <groupId>org.springframework.cloud</groupId>
        <artifactId>spring-cloud-starter-netflix-eureka-server</artifactId>
    </dependency>
</dependencies>
```

#### 4.2.2 启动类配置

```java
@SpringBootApplication
@EnableEurekaServer
public class EurekaServerApplication {
    public static void main(String[] args) {
        SpringApplication.run(EurekaServerApplication.class, args);
    }
}
```

#### 4.2.3 配置文件

```yaml
server:
  port: 8080

spring:
  application:
    name: eureka-server

eureka:
  instance:
    hostname: localhost
  client:
    # 不向注册中心注册自己
    register-with-eureka: false
    # 不从注册中心获取服务列表
    fetch-registry: false
    service-url:
      defaultZone: http://${eureka.instance.hostname}:${server.port}/eureka/
  server:
    # 关闭自我保护模式（开发环境）
    enable-self-preservation: false
    # 清理间隔（单位：毫秒）
    eviction-interval-timer-in-ms: 2000
```

### 4.3 Eureka Client 配置

#### 4.3.1 添加依赖

```xml
<dependency>
    <groupId>org.springframework.cloud</groupId>
    <artifactId>spring-cloud-starter-netflix-eureka-client</artifactId>
</dependency>
```

#### 4.3.2 启动类配置

```java
@SpringBootApplication
@EnableEurekaClient
public class UserServiceApplication {
    public static void main(String[] args) {
        SpringApplication.run(UserServiceApplication.class, args);
    }
}
```

#### 4.3.3 配置文件

```yaml
server:
  port: 9090

spring:
  application:
    name: user-service

eureka:
  client:
    service-url:
      defaultZone: http://localhost:8080/eureka/
  instance:
    # 使用 IP 地址注册
    prefer-ip-address: true
    # 实例 ID
    instance-id: ${spring.cloud.client.ip-address}:${server.port}
    # 心跳间隔
    lease-renewal-interval-in-seconds: 10
    # 服务失效时间
    lease-expiration-duration-in-seconds: 30
```

### 4.4 Eureka 自我保护机制

#### 4.4.1 什么是自我保护机制？

当 Eureka Server 在短时间内丢失过多客户端时（可能发生了网络分区故障），那么这个节点就会进入自我保护模式。

#### 4.4.2 自我保护机制的作用

- **保护注册信息**：不会删除服务注册信息
- **保证可用性**：宁可保留错误的服务注册信息，也不盲目注销任何可能健康的服务实例

#### 4.4.3 开发环境配置

```yaml
eureka:
  server:
    # 关闭自我保护模式
    enable-self-preservation: false
    # 设置清理间隔（单位：毫秒，默认是60*1000）
    eviction-interval-timer-in-ms: 2000
  client:
    # 设置心跳间隔（单位：秒，默认是30）
    lease-renewal-interval-in-seconds: 10
    # 设置服务失效时间（单位：秒，默认是90）
    lease-expiration-duration-in-seconds: 30
```

## 5. 服务间通信

### 5.1 OpenFeign 简介

OpenFeign 是一个声明式的 HTTP 客户端，它使得编写 HTTP 客户端变得更加简单。

### 5.2 OpenFeign 的优势

1. **声明式**：通过注解定义接口
2. **集成负载均衡**：自动集成 Ribbon
3. **支持多种编码器**：JSON、XML 等
4. **可插拔**：支持多种 HTTP 客户端

### 6.2 负载均衡策略

#### 6.2.1 轮询策略（默认）

### 6.3 自定义负载均衡策略

```java
public class WeightedLoadBalancer implements ReactorServiceInstanceLoadBalancer {
    
    private final String serviceId;
    private final ObjectProvider<ServiceInstanceListSupplier> serviceInstanceListSupplierProvider;
    
    public WeightedLoadBalancer(ObjectProvider<ServiceInstanceListSupplier> serviceInstanceListSupplierProvider,
                               String serviceId) {
        this.serviceId = serviceId;
        this.serviceInstanceListSupplierProvider = serviceInstanceListSupplierProvider;
    }
    
    @Override
    public Mono<Response<ServiceInstance>> choose(Request request) {
        ServiceInstanceListSupplier supplier = serviceInstanceListSupplierProvider
                .getIfAvailable(NoopServiceInstanceListSupplier::new);
        return supplier.get(request).next()
                .map(serviceInstances -> processInstanceResponse(serviceInstances));
    }
    
    private Response<ServiceInstance> processInstanceResponse(List<ServiceInstance> serviceInstances) {
        if (serviceInstances.isEmpty()) {
            return new EmptyResponse();
        }
        
        // 实现加权选择逻辑
        ServiceInstance selectedInstance = selectByWeight(serviceInstances);
        return new DefaultResponse(selectedInstance);
    }
    
    private ServiceInstance selectByWeight(List<ServiceInstance> serviceInstances) {
        // 加权选择算法实现
        // 这里简化为随机选择
        int index = new Random().nextInt(serviceInstances.size());
        return serviceInstances.get(index);
    }
}
```

    private UserService userService;
    
    @Value("${server.port}")
    private String port;

     * 添加用户
     */

        return userService.add(user);

     * 获取用户信息
     * 包含模拟延迟和异常处理，用于演示微服务的容错机制
     */
    @GetMapping(path = "/user", produces = MediaType.APPLICATION_JSON_VALUE)
    public UserVO get(@RequestParam("id") Long id) {
        try {
            // 模拟随机延迟（0-15秒）
            Thread.sleep((long) (Math.random() * 15000));
            
            User user = userService.get(id);
            if (user == null) {
                throw new ResponseStatusException(HttpStatus.NOT_FOUND, 
                    "User with id " + id + " not found");
            }
            
            return new UserVO(user.getId(), user.getName(), user.getPwd());
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
            throw new ResponseStatusException(HttpStatus.INTERNAL_SERVER_ERROR, 
                "Service interrupted", e);
        } catch (Exception e) {
            throw new ResponseStatusException(HttpStatus.NOT_FOUND, 
                "User with id " + id + " not found", e);
        }
    }
    
    /**
     * 获取服务端口，用于测试负载均衡
     */
    @GetMapping("/port")
    public String port() {
        return "User service is running on port: " + port;

## 9. 最佳实践

### 9.1 服务设计原则

#### 9.1.1 单一职责原则

每个微服务应该只负责一个业务领域：

```text
✅ 好的设计：
- 用户服务：用户注册、登录、信息管理
- 订单服务：订单创建、查询、状态更新
- 支付服务：支付处理、退款、账单

❌ 不好的设计：
- 用户订单服务：用户管理 + 订单管理（职责过多）
```

#### 9.1.2 数据库分离

每个服务应该有自己的数据库：

```text
✅ 好的设计：
User Service → User Database
Order Service → Order Database
Payment Service → Payment Database

❌ 不好的设计：
User Service ↘
              → Shared Database
Order Service ↗
```

## 10. 常见问题与解决方案

### 10.1 服务启动问题

#### 问题：服务无法注册到 Eureka

**症状：**

```text
com.netflix.discovery.DiscoveryClient: DiscoveryClient_USER-SERVICE - was unable to send heartbeat!
```

**解决方案：**

1. 检查 Eureka Server 是否正常运行
2. 检查网络连接
3. 验证配置文件中的 Eureka 地址

```yaml
eureka:
  client:
    service-url:
      defaultZone: http://eureka-server:8080/eureka  # 确保地址正确
```

#### 问题：数据库连接失败

**症状：**

```text
com.mysql.cj.jdbc.exceptions.CommunicationsException: Communications link failure
```

**解决方案：**

1. 检查数据库服务是否启动
2. 验证连接字符串
3. 检查网络连接

```yaml
spring:
  datasource:
    url: jdbc:mysql://mysql:3306/user?charset=utf8mb4&useSSL=false&serverTimezone=UTC
    username: root
    password: dangerous
    driver-class-name: com.mysql.cj.jdbc.Driver
```

### 10.2 服务调用问题

#### 问题：Feign 调用超时

**症状：**

```text
feign.RetryableException: Read timed out executing GET http://user-service/user
```

**解决方案：**

1. 增加超时时间
2. 配置重试机制
3. 检查目标服务性能

```yaml
feign:
  client:
    config:
      user-service:
        connect-timeout: 5000
        read-timeout: 10000
```

#### 问题：负载均衡不生效

**症状：**
请求总是路由到同一个服务实例

**解决方案：**

1. 确保多个服务实例都已注册
2. 检查负载均衡配置
3. 验证服务健康状态

### 10.4 部署问题

#### 问题：Kubernetes 中服务无法访问

**解决方案：**

确保 Service 选择器与 Pod 标签匹配：

```yaml
# Service

kind: Service
metadata:
  name: user-service
spec:
  selector:
    app: user-service  # 必须与 Pod 标签匹配
  ports:
  - port: 9090
    targetPort: 9090

---
# Deployment
apiVersion: apps/v1
kind: Deployment
metadata:
  name: user-service
spec:
  template:
    metadata:
      labels:
        app: user-service  # 与 Service 选择器匹配
```
