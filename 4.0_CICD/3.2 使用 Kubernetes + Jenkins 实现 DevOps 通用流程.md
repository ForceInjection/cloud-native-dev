# Jenkins + Kubernetes CI/CD 流水线实战教程

基于 Spring Boot + Prometheus 监控的完整 DevOps 实践

---

## 1. 教程概述

本教程将指导您从零开始构建一个完整的 Jenkins CI/CD 流水线，实现 Spring Boot 应用的自动化构建、测试、部署和监控。通过本教程，您将学会：

- 配置 Jenkins Master/Slave 架构
- 使用 Docker 进行应用容器化
- 集成 Harbor 镜像仓库
- 部署应用到 Kubernetes 集群
- 配置 Prometheus 监控

### 3.2 核心文件解析

#### 3.2.1 Dockerfile 分析

```dockerfile
# 第一阶段：构建阶段
FROM maven:3.8.7-eclipse-temurin-8 AS builder

# 设置工作目录
WORKDIR /usr/src/mymaven

# 复制 Maven 配置文件
RUN mkdir -p /root/.m2
COPY settings.xml /root/.m2/settings.xml

# 复制pom.xml和源代码
COPY pom.xml .
COPY src ./src

# 构建项目
RUN mvn -B -DskipTests clean package

# 第二阶段：运行阶段
FROM eclipse-temurin:8u372-b07-jre-centos7

# 设置时区
RUN ln -sf /usr/share/zoneinfo/Asia/Shanghai /etc/localtime
RUN echo 'Asia/Shanghai' >/etc/timezone

# 设置环境变量
ENV JAVA_OPTS ''

# 设置工作目录
WORKDIR /app

# 从构建阶段复制构建结果
COPY --from=builder /usr/src/mymaven/target/prometheus-test-demo-0.0.1-SNAPSHOT.jar ./prometheus-test-demo-0.0.1-SNAPSHOT.jar

# 启动命令
ENTRYPOINT ["sh", "-c", "set -e && java -XX:+PrintFlagsFinal \
                                           -XX:+HeapDumpOnOutOfMemoryError \
                                           -XX:HeapDumpPath=/heapdump/heapdump.hprof \
                                           -XX:+UnlockExperimentalVMOptions \
                                           -XX:+UseCGroupMemoryLimitForHeap \
                                           $JAVA_OPTS -jar prometheus-test-demo-0.0.1-SNAPSHOT.jar"]
```

**关键特性：**

1. **多阶段构建 (Multi-stage Build)**
   - **构建阶段**: 使用 `maven:3.8.7-eclipse-temurin-8` 镜像进行代码编译
   - **运行阶段**: 使用 `eclipse-temurin:8u372-b07-jre-centos7` 轻量级 JRE 镜像
   - 显著减少最终镜像大小，提高安全性

2. **Maven 配置优化**
   - 复制 `settings.xml` 到容器内，使用阿里云镜像加速依赖下载
   - 分层复制 `pom.xml` 和源代码，利用 Docker 缓存机制

3. **生产级 JVM 配置**
   - `-XX:+HeapDumpOnOutOfMemoryError`: OOM 时自动生成堆转储
   - `-XX:+UseCGroupMemoryLimitForHeap`: 容器内存限制感知
   - `-XX:+PrintFlagsFinal`: 输出最终 JVM 参数便于调试

4. **时区和环境配置**
   - 设置为中国时区 (`Asia/Shanghai`)
   - 支持通过 `JAVA_OPTS` 环境变量动态调整 JVM 参数

**优势分析：**

- **镜像大小优化**: 多阶段构建避免在最终镜像中包含构建工具
- **构建效率**: 利用 Docker 层缓存和阿里云 Maven 镜像加速构建
- **生产就绪**: 包含完整的 JVM 监控和调试配置
- **容器化适配**: JVM 参数针对容器环境进行优化

## 4. Jenkins 流水线详解

### 4.1 流水线架构设计

本项目采用 **Master-Slave 分离架构**：

- **Master 节点**：负责代码构建、镜像制作和推送
- **Slave 节点**：负责 Kubernetes 部署操作

### 4.2 Pipeline 配置

#### 4.2.1 环境变量管理

流水线使用集中的环境变量管理：

```groovy
environment {
    HARBOR_REGISTRY = '172.22.83.19:30003'
    IMAGE_NAME = 'library/prometheus-test-demo'
    GIT_REPO = 'https://gitee.com/grissom_sh/prometheus-test-demo.git'
}
```

**环境变量说明：**

- `HARBOR_REGISTRY`: Harbor 镜像仓库地址
- `IMAGE_NAME`: 镜像名称和项目路径
- `GIT_REPO`: Git 仓库地址

#### 4.2.2 参数化配置

流水线支持以下参数化配置：

```groovy
parameters {
    string(name: 'NAMESPACE', defaultValue: 'default', description: 'Target namespace for deployment')
    string(name: 'MONITOR_NAMESPACE', defaultValue: 'monitor', description: 'Monitor namespace for ServiceMonitor')
}
```

**参数说明：**

- `NAMESPACE`: 应用部署的目标命名空间
- `MONITOR_NAMESPACE`: ServiceMonitor 部署的监控命名空间

### 4.3 流水线阶段详解

#### 阶段一：代码克隆 (Master 节点)

```groovy
stage('Clone Code') {
    agent {
        label 'master'
    }
    steps {
        echo "1.Git Clone Code"
        script {
            try {
                git url: "${env.GIT_REPO}"
            } catch (Exception e) {
                error "Git clone failed: ${e.getMessage()}"
            }
        }
    }
}
```

**功能说明：**

- 从 Gitee 仓库克隆最新代码，使用环境变量 `GIT_REPO`
- 在 Master 节点执行，确保代码可用性
- 添加错误处理机制，捕获 Git 克隆失败的异常

#### 阶段二：Docker 镜像构建 (Master 节点，包含 Maven 构建)

```groovy
stage('Image Build') {
    agent {
        label 'master'
    }
    steps {
        echo "2.Image Build Stage (包含 Maven 构建)"
        script {
            try {
                // 使用 Dockerfile 多阶段构建，包含 Maven 构建和镜像构建
                sh "docker build --cache-from ${env.HARBOR_REGISTRY}/${env.IMAGE_NAME}:latest -t ${env.HARBOR_REGISTRY}/${env.IMAGE_NAME}:${BUILD_NUMBER} ."
            } catch (Exception e) {
                error "Docker build failed: ${e.getMessage()}"
            }
        }
    }
}
```

**重要说明：**

- **多阶段构建优化**：使用 Dockerfile 多阶段构建，在构建阶段完成 Maven 编译，运行阶段使用轻量级 JRE 镜像
- **环境变量使用**：使用 `env.HARBOR_REGISTRY` 和 `env.IMAGE_NAME` 环境变量，提高配置的可维护性
- **构建缓存优化**：使用 `--cache-from` 参数利用之前构建的镜像层缓存，加速构建过程
- **版本标签统一**：使用 `BUILD_NUMBER` 作为镜像版本标签，确保镜像版本唯一性
- **错误处理**：添加 try-catch 块捕获 Docker 构建失败的异常

#### 阶段三：镜像推送 (Master 节点)

```groovy
stage('Push') {
    agent {
        label 'master'
    }
    steps {
        echo "3.Push Docker Image Stage"
        script {
            try {
                withCredentials([usernamePassword(credentialsId: 'harbor-credentials', 
                                                  usernameVariable: 'HARBOR_USER', 
                                                  passwordVariable: 'HARBOR_PASS')]) {
                    sh "docker login ${env.HARBOR_REGISTRY} -u $HARBOR_USER -p $HARBOR_PASS"
                    sh "docker push ${env.HARBOR_REGISTRY}/${env.IMAGE_NAME}:${BUILD_NUMBER}"
                }
            } catch (Exception e) {
                error "Docker push failed: ${e.getMessage()}"
            }
        }
    }
}
```

**安全最佳实践：**

- **凭据管理**：使用 Jenkins 凭据管理系统存储 Harbor 用户名和密码，避免硬编码敏感信息
- **环境变量**：使用 `env.HARBOR_REGISTRY` 和 `env.IMAGE_NAME` 环境变量，提高配置灵活性
- **错误处理**：添加异常捕获机制，确保推送失败时能及时发现和处理
- **凭据作用域**：`withCredentials` 块确保凭据只在需要时暴露，提高安全性

#### 阶段四：部署文件准备 (Slave 节点)

```groovy
node('slave') {
    container('jnlp-kubectl') {
        stage('Clone YAML') {
            echo "4. Git Clone YAML To Slave"
            script {
                try {
                    // 使用 checkout scm 获取当前流水线的源代码
                    checkout scm
                } catch (Exception e) {
                    error "Source code checkout failed: ${e.getMessage()}"
                }
            }
        }
        
        stage('Config YAML') {
            echo "5. Change YAML File Stage"
            sh 'sed -i "s/{VERSION}/${BUILD_NUMBER}/g" ./jenkins/scripts/prometheus-test-demo.yaml'
            sh 'sed -i "s/{NAMESPACE}/${NAMESPACE}/g" ./jenkins/scripts/prometheus-test-demo.yaml'
            sh 'sed -i "s/{MONITOR_NAMESPACE}/${MONITOR_NAMESPACE}/g" ./jenkins/scripts/prometheus-test-serviceMonitor.yaml'
            sh 'sed -i "s/{NAMESPACE}/${NAMESPACE}/g" ./jenkins/scripts/prometheus-test-serviceMonitor.yaml'

            sh 'cat ./jenkins/scripts/prometheus-test-demo.yaml'
            sh 'cat ./jenkins/scripts/prometheus-test-serviceMonitor.yaml'
        }
        
        stage('Deploy prometheus-test-demo') {
            echo "6. Deploy To K8s Stage"
            sh 'kubectl apply -f ./jenkins/scripts/prometheus-test-demo.yaml'
        }
        
        stage('Deploy prometheus-test-demo ServiceMonitor') {
            echo "7. Deploy ServiceMonitor To K8s Stage"
            script {
                try {
                    sh 'kubectl apply -f ./jenkins/scripts/prometheus-test-serviceMonitor.yaml'
                } catch (Exception e) {
                    error "ServiceMonitor deployment failed: ${e.getMessage()}"
                }
            }
        }
        
        stage('Health Check') {
            echo "8. Health Check Stage"
            script {
                try {
                    timeout(time: 5, unit: 'MINUTES') {
                        sh "kubectl wait --for=condition=ready pod -l app=prometheus-test-demo -n ${NAMESPACE} --timeout=300s"
                        echo "Application is healthy and ready!"
                    }
                } catch (Exception e) {
                    error "Health check failed: ${e.getMessage()}"
                }
            }
        }
    }
}
```

**配置优化说明：**

- **源代码获取**：使用 `checkout scm` 替代 `git url`，确保在 Kubernetes 环境中正确获取源代码
- **环境变量使用**：使用 `BUILD_NUMBER` 环境变量和流水线参数，提高配置灵活性
- **错误处理**：为源代码检出和 YAML 配置添加异常处理机制
- **配置验证**：添加 YAML 文件内容输出，便于调试和验证配置结果
- **变量统一**：统一使用 `BUILD_NUMBER` 替代 `BUILD_ID`，保持一致性

**部署说明：**

- 首先部署应用的 Deployment 和 Service
- 然后部署 ServiceMonitor 用于 Prometheus 监控
- 使用 `kubectl rollout status` 验证部署状态
- 添加健康检查确保应用正常运行

## 5. Kubernetes 部署配置

### 5.1 应用部署配置

参考 `ex4.2/jenkins/scripts/prometheus-test-demo.yaml` 文件：

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  labels:
    app: prometheus-test-demo
  name: prometheus-test-demo
  namespace: {NAMESPACE}
spec:
  replicas: 1
  selector:
    matchLabels:
      app: prometheus-test-demo
  template:
    metadata:
      annotations:
        prometheus.io/path: /actuator/prometheus
        prometheus.io/port: "8998"
        prometheus.io/scheme: http
        prometheus.io/scrape: "true"
      labels:
        app: prometheus-test-demo
    spec:
      containers:
        - image: 172.22.83.19:30003/library/prometheus-test-demo:{VERSION}
          name: prometheus-test-demo
---
apiVersion: v1
kind: Service
metadata:
  name: prometheus-test-demo
  labels:
    app: prometheus-test-demo
  namespace: {NAMESPACE}
spec:
  type: NodePort
  selector:
    app: prometheus-test-demo
  ports:
    - name: tcp
      protocol: TCP
      port: 8998
      targetPort: 8998
```

**配置要点：**

- 使用 NodePort 服务类型便于外部访问
- 添加 Prometheus 注解支持自动发现
- `{VERSION}` 占位符将被 Jenkins 替换为 `BUILD_NUMBER`
- 镜像地址使用环境变量 `HARBOR_REGISTRY` 和 `IMAGE_NAME` 动态配置

### 5.2 Prometheus 监控配置

参考 `ex4.2/jenkins/scripts/prometheus-test-serviceMonitor.yaml` 文件：

```yaml
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  labels:
    k8s-app: prometheus-test-demo
  name: prometheus-test-demo
  namespace: {MONITOR_NAMESPACE}
spec:
  endpoints:
  - interval: 30s
    port: tcp
    path: /actuator/prometheus
    scheme: 'http'
  selector:
    matchLabels:
      app: prometheus-test-demo
  namespaceSelector:
    matchNames:
    - {NAMESPACE}
```

**监控特性：**

- 30秒采集间隔
- 跨命名空间监控（monitor -> default）
- 自动发现带有指定标签的服务

#### 8.2.1 自定义业务指标

```java
@RestController
public class MetricsController {
    
    private final Counter requestCounter;
    private final Timer requestTimer;
    
    public MetricsController(MeterRegistry meterRegistry) {
        this.requestCounter = Counter.builder("custom_requests_total")
            .description("Total number of requests")
            .register(meterRegistry);
            
        this.requestTimer = Timer.builder("custom_request_duration")
            .description("Request duration")
            .register(meterRegistry);
    }
    
    @GetMapping("/api/data")
    public String getData() {
        return requestTimer.recordCallable(() -> {
            requestCounter.increment();
            // 业务逻辑
            return "data";
        });
    }
}
```
