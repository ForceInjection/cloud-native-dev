# Jenkins + Kubernetes CI/CD 流水线实战教程

基于 Spring Boot + Prometheus 监控的完整 DevOps 实践

---

## 1. 教程概述

本教程将指导您从零开始构建一个完整的 Jenkins CI/CD 流水线，实现 Spring Boot 应用的自动化构建、测试、部署和监控。通过本教程，您将学会：

- 配置 Jenkins Master/Slave 架构
- 使用 Docker 进行应用容器化
- 集成 Harbor 镜像仓库
- 部署应用到 Kubernetes 集群
- 配置 Prometheus 监控

## 4. Jenkins 流水线详解

### 4.1 流水线架构设计

本项目采用 **Master-Slave 分离架构**：

- **Master 节点**：负责代码构建、镜像制作和推送
- **Slave 节点**：负责 Kubernetes 部署操作

### 4.2 流水线阶段详解

#### 阶段一：代码克隆 (Master 节点)

```groovy
stage('Clone Code') {
    agent {
        label 'master'
    }
    steps {
        echo "1.Git Clone Code"
        git url: "https://gitee.com/sundandan1/prometheus-test-demo.git"
    }
}
```

**功能说明：**

- 从 Gitee 仓库克隆最新代码
- 在 Master 节点执行，确保代码可用性

#### 阶段二：Maven 构建 (Docker 容器)

```groovy
stage ('Maven Build') {
    agent {
        docker {
            image 'maven:3-alpine'
            args '-v /root/.m2:/root/.m2'
        }
    }
    steps {
        echo "2.Maven Build Stage"
        sh 'mvn -B -DskipTests clean package'
    }
}
```

**关键特性：**

- 使用 Docker 容器隔离构建环境
- 挂载 Maven 本地仓库缓存
- 跳过测试以加速构建（生产环境建议保留测试）

#### 阶段三：Docker 镜像构建 (Master 节点)

```groovy
stage('Image Build') {
    agent {
        label 'master'
    }
    steps {
        echo "3.Image Build Stage"
        sh 'docker build -f Dockerfile --build-arg jar_name=target/prometheus-test-demo-0.0.1-SNAPSHOT.jar -t prometheus-test-demo:${BUILD_ID} . '
        sh 'docker tag prometheus-test-demo:${BUILD_ID} 172.22.83.19:30003/library/prometheus-test-demo:${BUILD_ID}'
    }
}
```

**重要说明：**

- 使用 `BUILD_ID` 作为镜像版本标签
- 为 Harbor 仓库打标签
- 确保镜像版本唯一性

#### 阶段四：镜像推送 (Master 节点)

```groovy
stage('Push') {
    agent {
        label 'master'
    }
    steps {
        echo "4.Push Docker Image Stage"
        sh "docker login --username=admin 172.22.83.19:30003 -p Harbor12345"
        sh "docker push 172.22.83.19:30003/library/prometheus-test-demo:${BUILD_ID}"
    }
}
```

**安全提醒：**

- 生产环境应使用 Jenkins 凭据管理
- 避免在代码中硬编码密码

#### 阶段五：部署文件准备 (Slave 节点)

```groovy
node('slave') {
    container('jnlp-kubectl') {
        stage('Clone YAML') {
            echo "5. Git Clone YAML To Slave"
            git url: "https://gitee.com/sundandan1/prometheus-test-demo.git"
        }
        
        stage('Config YAML') {
            echo "6. Change YAML File Stage"
            sh 'sed -i "s#{VERSION}#${BUILD_ID}#g" ./jenkins/scripts/prometheus-test-demo.yaml'
        }
    }
}
```

**功能说明：**

- 在 Slave 节点重新克隆代码（获取部署文件）
- 使用 `sed` 命令替换 YAML 中的版本占位符

#### 阶段六：Kubernetes 部署 (Slave 节点)

```groovy
stage('Deploy YAML') {
    echo "7. Deploy To K8s Stage"
    sh 'kubectl apply -f ./jenkins/scripts/prometheus-test-demo.yaml'
}

stage('Deploy ServiceMonitor YAML') {
    echo "8. Deploy ServiceMonitor To K8s Stage"
    sh 'kubectl apply -f ./jenkins/scripts/prometheus-test-serviceMonitor.yaml'
}
```

## 5. Kubernetes 部署配置

### 5.1 应用部署配置

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  labels:
    app: prometheus-test-demo
  name: prometheus-test-demo
  namespace: default
spec:
  replicas: 1
  selector:
    matchLabels:
      app: prometheus-test-demo
  template:
    metadata:
      annotations:
        prometheus.io/path: /actuator/prometheus
        prometheus.io/port: "8998"
        prometheus.io/scheme: http
        prometheus.io/scrape: "true"
      labels:
        app: prometheus-test-demo
    spec:
      containers:
      - image: 172.22.83.19:30003/library/prometheus-test-demo:{VERSION}
        name: prometheus-test-demo
---
apiVersion: v1
kind: Service
metadata:
  name: prometheus-test-demo
  labels:
    app: prometheus-test-demo
spec:
  type: NodePort
  selector:
    app: prometheus-test-demo
  ports:
  - name: tcp
    protocol: TCP
    port: 8998
    targetPort: 8998
```

**配置要点：**

- 使用 NodePort 服务类型便于外部访问
- 添加 Prometheus 注解支持自动发现
- `{VERSION}` 占位符将被 Jenkins 替换为 `BUILD_ID`

### 5.2 Prometheus 监控配置

```yaml
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  labels:
    k8s-app: prometheus-test-demo
  name: prometheus-test-demo
  namespace: monitor
spec:
  endpoints:
  - interval: 30s
    port: tcp
    path: /actuator/prometheus
    scheme: 'http'
  selector:
    matchLabels:
      app: prometheus-test-demo
  namespaceSelector:
    matchNames:
    - default
```

**监控特性：**

- 30秒采集间隔
- 跨命名空间监控（monitor -> default）
- 自动发现带有指定标签的服务

### 8.2 性能优化建议

#### 8.2.1 Maven 构建优化

```groovy
// 使用并行构建
sh 'mvn -B -T 1C -DskipTests clean package'

// 使用本地仓库缓存
args '-v /root/.m2:/root/.m2 -v maven-cache:/root/.m2/repository'
```

#### 8.2.2 Docker 镜像优化

```dockerfile
# 使用多阶段构建
FROM maven:3-alpine AS builder
WORKDIR /app
COPY pom.xml .
RUN mvn dependency:go-offline
COPY src ./src
RUN mvn package -DskipTests

FROM openjdk:8-jre-alpine
COPY --from=builder /app/target/*.jar app.jar
ENTRYPOINT ["java", "-jar", "/app.jar"]
```

### 8.3 监控增强

#### 8.3.1 自定义业务指标

```java
@RestController
public class MetricsController {
    
    private final Counter requestCounter;
    private final Timer requestTimer;
    
    public MetricsController(MeterRegistry meterRegistry) {
        this.requestCounter = Counter.builder("custom_requests_total")
            .description("Total number of requests")
            .register(meterRegistry);
            
        this.requestTimer = Timer.builder("custom_request_duration")
            .description("Request duration")
            .register(meterRegistry);
    }
    
    @GetMapping("/api/data")
    public String getData() {
        return requestTimer.recordCallable(() -> {
            requestCounter.increment();
            // 业务逻辑
            return "data";
        });
    }
}
```
